## 用法（事后辩论武器，不是事前清单）

agent 坚持要加固而你认为不必时，**按 ID 质询**：「你的提案与 HERO-X-NNN 有何不同？」——这个问题有答案；「只是谨慎」没有。**先读反例再用**：`H-003` / `E-004` / `R-004` / `R-005` 四件是「平读规则会压掉真发现」的记录——如果 agent 引用**反例**回击你，它可能是对的。

## H — Hashing

| ID | 一句形态 |
|---|---|
| HERO-H-001 | 为比对两个表格给每行算哈希——直接比单元格就能回答 |
| HERO-H-002 | 满工作树写没人读的校验和文件——不是校验，是残渣 |
| HERO-H-003 | 【反例】摘要比对跳过重读未变大文件——真节省，平禁哈希因此是错的 |

## E — Edge cases

| ID | 一句形态 |
|---|---|
| HERO-E-001 | 给没有用户/部署的玩具应用做一整天账号安全 |
| HERO-E-002 | 给离线测试平台加防篡改/对抗层——防御来自类别，不来自本项目 |
| HERO-E-003 | 本地小改动配版本迁移路径——没有发布就没有迁移 |
| HERO-E-004 | 【反例】听似罕见的裸字符串缺陷——项目自己的文档示例就会产生，每个照文档走的用户都中 |

## R — Rubrics

| ID | 一句形态 |
|---|---|
| HERO-R-001 | 整夜对抗性自审，需求没动——无活性不确定性的再验证不是验证 |
| HERO-R-002 | 对任何提交都给不通过的审阅者——永不通过的结论不带信息 |
| HERO-R-003 | 叶子模块改一行却全量重跑套件两次——爆炸半径才是判据，不是行数 |
| HERO-R-004 | 【反例】从未端到端跑过一次的调度器带病上线——欠一次六十秒的冒烟 |
| HERO-R-005 | 【反例】改共享序列化格式后全量跑消费方——不确定性有界且结果改变下一步，是成比例的 |
| HERO-R-006 | 研究流水线被审计循环置换（协议冻结/门禁/评审包排队，计算始终未跑）——完整案例见上游 quant-research-audit-loop |

## O — Overbuild

| ID | 一句形态 |
|---|---|
| HERO-O-001 | 守卫守卫守卫——每层理由是上一层，不是需求；无自然止点即铁证 |
| HERO-O-002 | 防御代码多于实现——判据不是比例，是逐条守卫能否指名触发它的输入 |
| HERO-O-003 | 给一次简单调用配全套会话加盐机器——安全工程师本人都判过度 |
| HERO-O-004 | 单任务起多子代理扇出重复读同一代码——成本随代理数涨，信息不涨 |
| HERO-O-005 | 每个可恢复的普通失败都固化成永久版本树/准入契约/不可变清单 |
