# 防过度设计（anti-overdesign）

> Provenance：蒸馏自 HERO-Anti-OverDefense（MIT，2026-09-10 立项拍板 [ADR 2026-09-10-m1-guard-anti-overdesign](../../.agents/notes/implemented/architecture/2026-09-10-m1-guard-anti-overdesign.md) Decision 2；上游版权集中于 [THIRD-PARTY-NOTICES.md](../../THIRD-PARTY-NOTICES.md)）。提炼后搬迁，非逐字节搬运：四族命名与三刀判据保留原形，规则中文化并按本仓语汇改写；本篇 = 完整蒸馏的家，常驻面只留[精简契约块](../../AGENTS.md#防过度设计范围契约)，案例目录[索引](../research/anti-overdefense-cases-index.md)不进任何加载面。

## 1. 定位与预期（先读这个）

- **它防的是一类失败**：agent 把「能提升信心」悄悄升格为「所以必须建和查」——把可选的不确定性缩减当成主任务。症状 = 交付物外围筑起堡垒（校验和/防御层/评分表/迁移框架），而主任务没做完。
- **预期口径 = 护栏非开关**（上游作者与社区共识原话：helps, not a switch）：有些运行仍会筑墙。本契约是 defeasible 自然语言配置，不是 enforcement——更强的具体指令可以压过它（见 §8）。
- **不建机器闸**：过度防御机器不可判（HERO-O 本尊 = 「为守卫再造守卫」）；同型判据已在 C15 两候选实证过（文件名契约闸/上帝类闸均判不立，[B4 ADR Decision 6](../../.agents/notes/implemented/architecture/2026-09-08-b4-mount-wiring.md)）。本篇与常驻块是本域全部防面。

## 2. 四族 + 兄弟形态

根因假设（上游标注为假设非定论）：agent 优化「不被怪罪」而非「活好」。

| 族 | 形态 | 判据 |
|---|---|---|
| **H — Hashing** | 无人真正受益的校验和/指纹 | 哈希必须**替代实质上更贵的操作**且结果改变下一步；「有东西读它」太弱（逐行哈希自己也读） |
| **E — Edge cases** | 防御**这里**不会发生的输入 | 关键词是「这里」：经本项目受支持用法可达 = 真问题必报；「理论上构造得出」不算 |
| **R — Rubrics** | 机器替代判断——评分表/清单/对已定论的东西再验 | 症状：一整夜工作、完整审计轨迹、零功能 |
| **O — Overbuild** | 为没人要的未来造脚手架——feature flag/迁移框架/兼容层/守卫守卫守卫 | 一层守卫的理由是上一层守卫，不是需求 |

**兄弟形态**（不入四族，防分类学稀释）：**over-correction**（说东错了一点就搬到大西洋）；**defensive prose**（交付物成答辩记录——判据家 = 本篇 §3 Rule 7，归并声明见 §6）；**stalling**（交菜单不选择——「为了不选错而停在原地本身就是选错」；判据家 = 本篇 Rule 8）。

## 3. 契约九条（约束你提议什么修法，不约束你找什么）

凡是这里真的有问题都要报——包括听起来罕见但本项目确实会产生的情况。

1. **不是安全攻防论文**：除非本项目另有说明，默认操作者是自己机器上的合作者；真有对手它会写明，以那个范围为准。校验欢迎，过度防御禁止。
2. **哈希/校验和/指纹**只在替代实质上更贵的操作、且结果改变下一步做什么时才加。
3. **不为这里不会发生的情况**加 feature flag、迁移框架、兼容层、包装层。
4. **不钻牛角尖**：冷门编码、符号链接竞态、RTL 文本、毫秒级竞态不在范围内，除非经本项目受支持用法可达（文档示例、公开接口、真实数据）。可达即可，无需复现；「理论上构造得出」不算。
5. **该判断的地方就判断**：不换评分表、检查清单，或对已定论的东西再跑一遍校验。
6. **例外照常**：用户、本项目约定、更高优先级规则明确要求的安全/迁移/校验/审阅是被要求的，是活儿本身，不算范围外。
7. **交付物不是答辩记录**：成立的直说；注意事项集中到专门一节（Limitations/已知问题），不每段缀免责；「别提 X」= X 不存在（不是「我们不讨论 X」）；中间报错、被放弃的方案、改稿痕迹不是内容。围绕最强结果组织——是发布会，不是工作汇报。不占优的数字是取舍就说成取舍，不是就平实陈述，都不写成认输；数字本身照样留在表里。
8. **推进本身是交付的一部分**：几个方案都合理时选一个并写明取舍——只有分歧真的大、或选错难回头才升级为提问。不挡住目标的细节记下来接着走，不是先停下解决它。为了不选错而停在原地，本身就是选错。
9. **不留生成/纠偏痕迹**：最终产出（代码/注释/commit message/文档/总结）只呈现正确的最终结果，当作一开始就这么写——不提中间报错、试错纠偏、被放弃的方案、「为什么没做 X」；不出现 AI 辅助标记（署名、模型腔过渡语、「以下是」开场白）。措辞详略贴合项目已有风格。

**核心判据（跑任何检查前先答）**：这次运行会检测出什么具体的失败？真出现了我下一步会做什么不同的事？答不上来就别跑。判据要命名一个**仍然活着的**不确定性（不知道、且这次运行能定案的事）；「能检测出回归、出了我就修」套在任何检查上都成立，不算回答。

**诚实限定（上游勘误在案，照单接受）**：核心判据确实越界约束了搜索面——它不豁免「对已有怀疑的缺陷保持沉默」。能指名缺的证据与代价时，说出来，并说清要跑什么才能定案。

**对的就说对**。不要为了交差硬找问题。

## 4. 三刀（规则迭代修正记录——判据的边界）

- **Find versus propose**：契约约束**修法**，不约束**找问题**。写成「别报 corner case」会压掉真 bug；判据不是「听起来多罕见」，是「在这里可达吗」。精简版常被读窄，本条是纠偏。
- **Smoke versus theatre**：冒烟不是过度防御，是与现实最便宜的接触；但「便宜所以总跑」是错的——真跑已覆盖同路径时，另跑冒烟本身就是戏剧。判据同 §3 核心判据（命名仍然活着的不确定性；改了共享序列化格式后跑消费方 = 不确定性有界且结果改变下一步动作，是成比例的）。
- **Hash as cache versus evidence**：平禁哈希是错的（比对摘要跳过重读大文件是真节省）；「有东西读」又太弱。分界 = 哈希**替代了什么**。

## 5. 校准形状（例子不是清单——真发现不因「长得像」被驳回）

已见的（防这类）：

- H：为比对两个表格给每行算哈希——直接比单元格就能回答
- H：写一堆没人读的校验和文件
- E：给没有用户、没有部署的应用做账号加固
- R：整夜审计自己的补丁，功能一行没写
- R：对任何提交都给不通过的审阅者
- O：一层守卫的理由是上一层守卫，而不是需求

长得像但不是的（这些要报）：

- ✓ 用摘要比对跳过重读一个你已经有的大文件
- ✓ 本项目自己的文档示例就会产生的那种「听起来罕见」的输入

## 8. 何时开始、何时结束（最可能咬人的失败模式）

上游作者点名的首要失败：**同一提示里的具体重流程会压过泛化克制**——十二阶段协议冻结打赢「只做需要的检查」。对策不是重复契约，是**具体流程自己写清何时开始/结束**：冻结/审计/门禁类义务必须有终止条件，无界阶段清单每次都赢。本仓流程卡的「每个功能批次完成即执行收尾、不积压」即此纪律的实例；新增重流程时同变更写清终止条件。
