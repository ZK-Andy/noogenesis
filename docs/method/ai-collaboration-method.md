# AI 协作体系方法（种子）

> Provenance：回收自 dotnet-deepseek-harness-desktop `.plan/ai-collaboration-method.md`（MIT，2026-09-05；该文件在源仓 git 外、易失，故入库）。差异：HANDOFF/journal 改为入 git（ADR `2026-09-05-journal-in-git`）；verify-md-links 改为纳入 skills/（引入即适配）；技能前缀 noo-*；门禁清单更新为本仓七件；删除源仓"项目肉"节（本仓即第一实践村）。
>
> 本文是**跨项目通用**的 AI 协作开发体系：理念原理 + 可复用形制骨架，与语言/平台无关。新项目**不要整份照搬**（那是强行嫁接）：先读理念建立判断，再用形制骨架搭最小起点，然后随项目自己长。

---

## 一、理念原理

### 1. 每个事实只有一个家

一条规则、一个决策、一段踩坑，**只能有一个权威落点**。写新内容先 `grep` 去重，留给「家」一处，别处只放链接。

| 内容类型 | 家 |
|---|---|
| 一条规则 | AGENTS.md 对应节 + 链接 |
| 一次决策（为什么这么做、放弃了什么） | ADR（Agent Note） |
| 一个踩坑 / 判别经验 | cookbook |
| 一个契约/行为约定 | README / 方法论文档（docs/method/） |

反例：同一规则四处抄，改一处漏三处 → 规则打架、不可追踪。这正是「没人真正遵守」的根源。

### 2. 先长后立，不强行嫁接

- **家是长出来的**：层级不一次铺满——架构出现才建 architecture 文档，出事才建 postmortem，流程成熟才建 cookbook。**固定的是「一个事实一个家」，不是「九个空目录」。**
- **不要从外部抄一套「宪法」再往里填**：先让项目跑起来、攒行为证据，再从行为里提炼理念（见理念四骨）。「先立宪法再堆功能」是顺序倒置。
- **判断强行嫁接**：一个实践如果不是从这个项目真实需求里长出来的，而是「因为他项目有所以我也要」，它大概率是负担。真正的种子是**方法论**，不是**结论模板**。

### 3. 理念四骨（检验一个「理念」是不是真的理念）

一个候选理念要成立，须同时满足：

1. **说自己**——说的是自己（不是替用户/市场下结论）。
2. **绝对无例外**——没有例外情形，不能「大多数时候如此」。
3. **无限生成实例**——能无限生成具体实例，不是一句空话。
4. **有禁止力**——它是否定性的，有一条边界告诉你「不能这样做」。

用法：候选公理拿四骨去卡。四骨通不过的，是**基础养料不是理念**；硬立成教条就是过度设计。

### 4. 决策记录（ADR）代替会话

**决定不消失在聊天/git log 里。** 非平凡变更必须同变更携带 ADR：它回答「为什么这么做、放弃了什么、需要什么验证」——评审看得见、可回放、可审计。`## Alternatives considered` 强制：「不记录比赢过什么的决定，必然招致重新辩论」。决策史与项目代码同 PR 走、归档冻结；与跨会话经验（未来心源演化引擎）的职责分界——**跟这个项目代码有关 → ADR；跟「怎么用 agent 干活」的可复用经验 → 演化资产**。

### 5. 门禁让规范「可执行」，不是「建议」

**可执行门禁是灵魂。** 一违反立刻被脚本/CI 拦住，这是 AI 协作体验区别于一般文档规范的核心：规范能机器强制就写进 `verify-*`，挂 hooks（快检查）+ CI（穷尽）；语义面（机器强制不了的）由评审代理显式兜底，并在流程里**列清单**防漏（见 [review.md](review.md)）。

### 6. 写当前状态，禁写变更史

durable 文档写**当前状态**，禁止 "previously / now / no longer / renamed"（slop）。变更史只进 commit / PR / ADR。这条最反直觉、也最有效。

## 二、形制骨架（结构，与语言/平台无关）

这些是**结构**不是内容。放法按「先长后立」——只搭本项目用得到的，空目录不预置。

```
<项目根>/
├── AGENTS.md                 # 根规则（agent 自动加载；常驻命令 + 链接，每条 1-3 行）
├── docs/                     # 知识层：method/ 方法论 + cookbook 踩坑（按需长）
├── .agents/
│   ├── AGENTS.md             # 协作层专属规则（≤300 词）
│   ├── skills/               # 项目技能（noo-* 目录束，agent 自动发现）
│   ├── notes/                # ADR 体系（README 规则 + proposed/implemented/rejected/archived）
│   └── workflows/            # 流程卡：会话模式/开收尾/开发/发版/调研
├── templates/                # adr-proposed / adr-implemented / agents-hierarchy
├── scripts/                  # verify-* 门禁 + change-scope（零依赖，随仓库走）
├── HANDOFF.md + HANDOFF-todos.md   # 交接家庭（入 git）
└── journal/                  # 会话叙事月卷（入 git；过程即资产）
```

**技能放置**：目录束 `<技能名>/SKILL.md`；frontmatter 必填 `name`（小写 kebab，前缀 `noo-`）+ `description`（Use when…，能被真实任务触发）；可选 `whenToUse` / `invocation`（如 `disable-model-invocation` 标手动调用）。技能随 agent 自动发现，无需注册。

**分层 AGENTS**：根文件只放常驻命令 + 链接（每条 1-3 行）；子树文件 ≤300 词、只写专属规则。字数预算由 `verify-doc-budgets.mts`（manifest 驱动）强制；超限处理序：迁移 → 精简 → 才提额度（manifest `_justify_bump` 留理由）。

**门禁分工**：hooks 只做快检查，CI 拥有穷尽矩阵；push 前按 diff 面选最窄检查（`change-scope.mts`），不默认全量。

**Git 纪律**：改写历史必须 `--force-with-lease=<branch>:<observed-oid>`，raw `--force` 永远禁止；过程资产（HANDOFF/journal）入 git。

## 三、技能写作规范（什么配写 skill、怎么写、怎么防写偏）

### 1. 值得写的判据（同时满足才写）

- **真实需要**：本项目已经遇到它、缺它有代价（不能是「上游有所以我也写」）；`description` 必须能被真实任务触发。
- **可复用**：会多次用到（一次性的用流程卡/文档，不包装成 skill）。
- **有判断**：不是「照做一遍」的脚本，而是「引导判断」——保留人的决策。

反例（不写）：绑死特定生态的单次操作；纯机械步骤（直接写进脚本/流程卡）。

### 2. 结构模板

每个 skill = 目录束 `<name>/SKILL.md`。正文遵循「引导清单」结构：

1. **定位开头**：`guidance, not a script` + 一句话核心主张。
2. **Sources of truth**：权威文档链接（`read, don't re-summarize`——引权威，不重述）；**一律指向本项目真实存在的「家」**。
3. **核心方法**：分类学/清单/判别标准，含「什么不算/边界」。
4. **工作流**：分步可执行（先 scope → 再审计 → 再修 → 再验证）。
5. **验证与报告**：跑哪些核对、报告什么。

### 3. 从上游/别处吸收的方法

- **吸收方法，不照搬文件**：上游 skill 的**方法**（分类学、清单、判别标准）通用则采纳；**引用**换成本项目等价物。
- **引用以「本项目能解析」为准**：能解析的指向等价物；解析不了的背景链接**删除**。
- **不硬映射**：不存在对应物的，不要强行指向「看起来像」的本地文档（那是嫁接）。

### 4. 机械验证（防写偏）

能机械校验的是**格式合规**（DSH 能否加载、内链不烂、结构齐）；**不能**机械校验的是内容质量——靠对照规范写 + 评审兜底。`scripts/verify-skill-format.mts` 校验：frontmatter（name 小写 kebab + description 非空）、目录束结构（无根级 README）、**内链强制检查 skills/**（默认排除它掩盖断链——frecency 11 技能全死链的教训）、必要结构段（防只写空话）。

## 四、分发与生长（怎么用本文）

- 新项目**不看第一实践村的肉**，只取**理念 + 形制**；上手 = 建最小骨架 + 根 AGENTS.md + verify-adr-format → 跑起来 → 攒行为。
- **生长循环**：先发小功能 → 攒行为证据（哪条被遵守/被绕过/踩坑）→ 从行为提炼理念（过四骨）→ 落档（决策进 ADR，通用经验进演化资产）→ 首版后逐条复盘「保留/改造/放弃」。
- **该不该引入某实践**：项目已真实遇到它、缺它有代价 → 引入；「别的项目有」→ 不引入；改「搬实践」为「搬形成实践的方法」。
