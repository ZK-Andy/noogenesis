## Problem

主设计 §7.1 把「答案盲选择」列为六条最小可信护栏之一：**候选比较绝不用金标，用 logprob / judge / 独立执行**（§7.2）。本仓此面零落地，且既有各面都已各自关门：

- `select` 只做字面匹配（命中即列，不排序）——排序 / 禁用 / 阈值 / 衰减已由记忆线一期 Decision 4 判不立（附触发条，第二期复核维持不重开）。
- `evaluate` 判的是**单**候选的合格性（门禁全绿 + 约束满足）；`solidify` 单候选入档；两者都不回答「≥2 个备选怎么选」。
- 「多候选择优」在本仓真实发生（ADR `## Alternatives considered` 强制、三审 findings 逐条裁决、方案备选拍板），但只按散文面的判断做，无判据、无通道定义。

批次表序 5 的备注把第一步写死：**先定判据再动手**（防造不可判定信号）。本仓与 JIT 的字面差异也必须先摊开，否则判据会照抄一组在本仓不存在的通道：引擎零网络零 LLM（骨架 D1）——logprob 与 judge 结构性不可用；文档域无可信改进分数（骨架 D4）、数值评分已判不立（护栏建设轮 Decision 2）——「分数越高越好」这条最自然的通道也已封。

## Decision

### C1（判据：候选比较 = 可判定代理信号的对照，不是评分）

四条判据，单源在本笔记：

1. **候选** = 同一演化目标下的 ≥2 个备选（候选基因文件 / 已入档基因 / 方案备选，含三审 findings 的处置）。
2. **通道封闭集 = `independent_execution` ∪ `observation`**。**金标类输入永不入通道**——金标 = 期望答案 / 基准或评测集真值 / 目标 diff（「应该长成什么样」的对照物）；候选作者自报分同样不入（它与金标同属「不经真实执行就能拿到的高信息量信号」，正是泄漏面）。
3. **读数必须可判定**：每个通道的值是确定性可复算的布尔或计数；不造序数评分、不加权、不做衰减。造不出可判定读数的维度**不立**（宁可少一个信号，不可多一个不可判定的信号）。
4. **引擎不排序、不择优**（本项也不建产出面）：择优时按逐候选的合格性与通道读数做对照，结论归人的判断（骨架 D2：信号发现的判断放在人与流程卡里，引擎只做匹配）。选择须可复盘：选了谁 / 依据哪个通道 / 比较了谁。

### C2（通道证成：本仓可用通道只有两条）

- **`independent_execution`** = 候选各自真跑确定性验证的结果（门禁 / 基因 `validation` 声明的验证命令）。它是 §7.2「测试用例 = 资产自带的验证命令」的可用部分：可判定、可复算、与被比较者独立。参考实现里这条对应沙箱执行验证。
- **`observation`** = 观测面 `(signal::gene) → {ok, fail}`（记忆线一期面）：基因被真实采用后由人显式记录的读数。它是「部署期无金标」下唯一有真实样本的代理信号面。该面的 `select` `advice:` 行是**建议档**（不排序 / 不禁用 / 无阈值 / 无衰减，[记忆线一期](2026-09-11-memory-line-phase1-observation-face.md) Decision 4），不构成自动择优面。
- **logprob / judge 判不可行**：引擎零 LLM 零网络（D1 一脉），本仓不引入模型调用。参考实现用它们，是因为它就在模型内部；本仓没有这个位置。将来若要引入，先重拍 D1，不在本项。
- **金标判不可入**：参考调研把选择期使用 benchmark 分明确标为 leakage；本仓文档域也确无金标（D4）。两层理由各自独立成立。
- **骨架 D4 点名的两个候选信号不做选择信号**（论证归各所有者）：评审 Blocker 数追踪 = 评审账（[护栏建设轮](2026-09-13-guardrail-construction-round.md) Decision 2，过程账非通道）；token 常驻注入度量 = §7.1-6 token 基线不变量的刻度。

### C3（机器面：判不立，附具名触发）

不新增命令、字段、记录件。逐条按本仓「跑检查前先答两问」核对（会检测出什么具体失败 → 真出现了下一步做什么不同）：

- **「候选比较命令」（≥2 候选并排跑确定性检查、输出对照表）**：新增判定面与现有面重叠——候选不合格本就进不了档（`evaluate` 拒红、`solidify` 拒不合格），命令的增量判定为零；质量侧无标可读，命令只能复述既有读数。**落败**。
- **「选择账」记录件（选了谁 / 压倒谁 / 依据哪个通道）**：选择的家已在 ADR `## Alternatives considered`（强制）与 journal，它们是复盘时真正被读的面；机器写账**无具名消费者**，而 schema 扩面 = 合同面 + 夹具 + 门禁成本一起进。**落败**。
- **触发条（任一到达即另立 ADR，本项不重开记忆线判裁）**：
  1. 出现「同一信号下 ≥2 个已入档基因需按代理信号优选」——沿用记忆线一期 Decision 4 的触发条（命中数逼近常驻注入上限，**或**观测样本量足以支撑排序）；
  2. 出现「选择不可从 ADR / journal 复盘」的跨会话真实场景（同一比较被反复重做且结论漂移）。
- **本项不构成序 4 B3 的触发**：B3 要的是「事后按执行记录横向比较影响面的消费者 + 区间锚点」；本项判的是**没有这样的消费者**，故 Capsule `blast_radius` 维持不进 schema，B3 触发条原样保留。

### C4（操作入口：根 AGENTS 评审检查项第 7 条）

判据是**语义面**——机器门禁判不了「本次择优是否用了金标」。本仓此类规则的家 = 根 AGENTS「评审检查项」（清单单一事实源，见 [review.md](../../../../docs/method/review.md) §5），故入口 = 新增第 7 条，评审按它核对本次 ≥2 备选择优是否答案盲、是否留痕。

## Alternatives considered

- **新增 `compare <候选...>` 命令**：落败——见 C3：增量判定被 `evaluate` / `solidify` 覆盖，且要多一个命令合同面（README 计数面、适配层、self-test 逐字金样）。「建了却没有它才拦得住的失败」= 脚手架。
- **新增选择账记录件（`events/` 新 kind 或观测面扩字段）**：落败——见 C3：无具名消费者；观测面现有 schema 是封闭六字段，扩它即扩合同面。
- **在引擎内实现 logprob / judge 通道，或照抄 JIT 的 `select_best(candidates)`**：落败——D1 结构性不可用（零网络零 LLM），引入等于重拍骨架；参考实现的可执行性来自模型内部通道（logprob）或第二次模型调用（judge），本仓两者都无，照抄只能得到一个空壳函数。
- **用数值评分 / rubric 排序候选**：落败——与 D4「文档域无可信改进分数」+ 护栏 Decision 2「不立数值评分」直接冲突，且会诱导为分值优化（改写作风格刷分），与 §7.1 第 3、6 条冲突。
- **立「候选比较」为新原语（`comparisons/` 落盘）**：落败——主设计 §5.1 原语清单不含它；无生产者、无消费者；新顶层目录准入四问（谁生产 / 谁消费 / 复算规则 / 失效面）一问不过。
- **在 `docs/method/` 立一篇方法论**：落败——判据只有四条，没有可写的 procedure；立篇即预铺空面，ADR + 评审检查项已足。
- **只在 ADR 立判据、不落评审检查项**：落败——语义面无操作入口即无对账点（评审不会主动读一条冷 ADR）；AGENTS 检查项正是该面的家。

## Consequences

- **单源与指针**：判据单源 = 本笔记；操作入口 = 根 AGENTS 评审检查项第 7 条；候选比较的书面临时形态仍是 ADR `## Alternatives considered` + 三审 findings 裁决。
- **零机器面变更**：引擎合同面（命令集 / schema / 门禁清单 / 事件键集）零变化，无新夹具、无新门禁条目。
- **相邻决策不受影响**：记忆线一期 Decision 4（不排序 / 不禁用 / 无阈值 / 无衰减）不重开；护栏 Decision 2（不立数值评分）加固；序 4 B3（Capsule `blast_radius`）触发未到达，写明。
- **邻近机制归口**：§7.2 余下两条不在本项——「子代理在新鲜沙箱自动执行验证」= 批次表序 43，「合并携带自校验证据」= 序 45。
- **强度上限（写明）**：本项立的是**判据**，不是执行装置；它约束「怎么比」，不提供「自动比」。「择优仍归人」是判据的一部分，不是待补的缺口。
- **批次表状态**：序 5 已收口，批次表对应行标 done 并指向本笔记。
