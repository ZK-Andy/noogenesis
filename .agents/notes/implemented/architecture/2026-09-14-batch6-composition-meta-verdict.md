## Problem

批次表把行 31–33 列为批次 6（P3 元演化）余项，游标 = 序 30 已落 [distill 命令 ADR](2026-09-14-distill-command.md)。本件过门：对三行做开工前取证，并逐条给终态判定。取证（2026-09-14 实读，本机单仓全量）：

- **行 31（组合：Capsule → 预设 / 流程）**：声明的依赖序 1（Capsule 原语）已交付，但输入面为零——`capsules/` 与 `mutations/` 两个目录均不存在，`events/2026-09.jsonl` 8 条记录全为 `gene.*`（零 Capsule、零 Mutation 实例）。输出面（DSH preset / profile）在宿主侧：`dsh --help` 实读 profile = 「按序叠加的 plugin-bundle patch 层」，组合入口 = `dsh plugin --profile <name> add`（把余参转发 pnpm 到 profile 目录）与 `dsh --profile <name> --from-default-profile <template>`（`--patch` 为额外 overlay）；落点 `$DSH_HOME/profiles/<name>/`（本机 `/home/zk/.dsh/profiles/` 实存 `dotnet-desktop` / `web` 两件）在会话工作区之外。行 36（批次 7 P4）已是同一能力（「胶囊组合成 preset / profile」，依赖序 1/25）。
- **行 32（策略自身可搜索，元演化）**：设计原型 = EvoX AutoPSO「把参数 + 学习 + 蜂群结构编入可搜索空间」（主设计 §11 参考对照）。搜索 = 在候选空间上按评价定向择优，而本仓三条已定判据分别封住评价通道：序 5 判据 C1-4「引擎不排序、不择优」、C2（logprob / judge 结构性不可用——引擎零 LLM 零网络）、骨架 D4（文档域无可信改进分数；数值评分判不立，[护栏建设轮](2026-09-13-guardrail-construction-round.md) Decision 2）。
- **行 33（长程递归演化）**：批次表明写依赖序 30–32；语义 = 自动触发多轮演化，而两条封条封住触发环：骨架 D2 站立规则（自动 Detect **默认关** + 逐源门槛；批次 3 四源逐条判不立，重议触发 T1–T3 具名）与 D4「运行不记」（观测面写权归人，自动写判不立）。

## Decision

### 1. 序 31 判不立——能力面归口行 36，触发条具名

三条理由各自独立成立：

1. **输入面零实例**（Problem 实读）：可组合者与组合消费者都不在场。
2. **同一能力在本表已有交付行**：行 36（P4 分发，依赖序 1/25）承载同样的产出面；其产出形状的渲染语义门 = 序 25（gene→skill 渲染语义，[开题轮](2026-09-14-batch5-opening-round.md) 判随贡献开放轮后置）。本行（P3）无独立于行 36 的增量——双行同能力即双家。
3. **宿主组合面非插件服务面**：组合入口是 CLI + profile 目录（落点在会话工作区外），把它做成引擎面会先跳过「谁消费」。

重议触发（任一到达即另立 ADR，本项不重开）：

- **T1**：`capsules/` 出现 ≥2 个真实实例，且出现「同一任务类型需成组注入（超出单基因 `select` 面）」的具名消费者。
- **T2**：序 25 渲染语义拍板——产出形状（预设 / 流程）先有渲染判据。
- **T3**：宿主给出插件侧 profile 组合 / 挂载服务面（当前实测只有 CLI + 目录面）。

### 2. 序 32 判不立——与序 5 C3-1 同面，不新立触发条

变异源半边已由序 30 `distill`（失败面 → 候选，人工在环）+ 人工策展承担；评价半边 = 序 5 通道封闭集（`independent_execution` / `observation`）+ `evaluate` 的单候选合格性。缺的正是「按信号在候选空间定向择优」——序 5 C1-4 明写引擎不排序不择优，C3-1 的触发条即本行的开工条件。无新事实即无重开依据。

重议触发（沿用）：序 5 C3-1——出现「同一信号下 ≥2 个已入档基因需按代理信号优选」，其判据沿用记忆线一期 Decision 4（命中数逼近常驻注入上限，**或**观测样本量足以支撑排序）。

### 3. 序 33 顺延（判不立）——依赖链 + 双封条

依赖序 30–32：32 判不立 ⇒ 递归环的择优段缺席；D2 站立规则封自动触发（四源全判不立）、D4 封自动写（观测写权归人）。为 O(0) 成功实例建自动多轮循环 = 脚手架。

重议触发：行 32 判立 **且** 某个 Detect 源经独立裁决件过 HERO 两问——该源的 T1–T3 是重开触发条，单条到达不等于过门。

### 4. 批次 6 收口

行 30 done（已有），行 31–33 落终态（本件 = 指针）；机制零变化；游标推进批次 7（序 34）。

## Alternatives considered

- **行 31 以「引擎产组合描述件」形态放行（读 N 个 Capsule 生成预设 / 流程描述文件）**：落败——零实例、无具名消费者，且与行 36 同面双家；新顶层目录准入四问（谁生产 / 谁消费 / 复算规则 / 失效面）消费一问不过。形态同序 5 C3「无具名消费者的记录件」与序 24「字段先于消费者即死字段」。
- **行 31 直接实现宿主 profile 生成（写 `$DSH_HOME/profiles/`）**：落败——落点在会话工作区之外，组合面是 CLI + pnpm（非插件服务面），且同样跳过消费者；先例 = A8 教训（宿主约束把设计上合理的面判不可实现）。
- **行 32 引入 logprob / judge 或自建数值评分以支撑「搜索」**：落败——撞骨架 D1/D4 与护栏 Decision 2，须先重拍骨架，不在本项。
- **行 32 以「只产候选、不排序」放行（即序 30 已落形态）**：落败——与序 30 同面，增量 = 0；「搜索」的判别动作恰是排序 / 择优。
- **行 33 提前接线自动多轮演化循环**：落败——撞 D2 站立规则与 D4；无成功实例的自动回环不在 [anti-overdesign 范围契约](../../../../docs/method/anti-overdesign.md) 之内（不检测出具体失败、也无「真出现了下一步做什么不同」的答案）。
- **三行拆成三份 ADR**：落败——三行同挂一次开工前取证与同一批收口，拆件只复制证据面（取舍同 [批次 4 重拍件](2026-09-14-memory-line-phase2-reshoot.md) Alternatives）。
