## Problem

批次表序 9 问：M1 技能守卫是否升为「重复违约 → 阻断」。前两件 ADR 已判不立，理由同为「该不该用技能是语义判断，机器给不出必报失败」，但两次只测了**触发面**（该命中而结构上未命中），没测**服从面**（advice 发行后模型是否照办）。本件补这一面——升格的价值完全取决于服从面。

取证（宿主会话卷实取，单机单仓，【探索性】）：样本 = `~/.dsh/sessions/--mnt-work-Noogenesis--/` 328 个卷目录（77 主会话 + 251 子会话，测量时点）。**实际扫描面 = 其中 183 份 `session.v3.jsonl.zstd`**（本口径只读该形态）；余 146 份是 `session.jsonl.zstd` / `session.v2.jsonl.zstd` 旧形态，全部 ≤2026-09-08（守卫装机前），复扫零命中。口径 = advice 注入事件（`agent/inbox/spliced` 且载荷含 `without loading the … skill` 行）与技能载入事件（`tool/call` 且 `data.name = "skill"`）按 `seq` 排序比较。**排除测量污染**——以 `agent/inbox/spliced` 为唯一判据（同一条 advice 另有 `user/message` 副本，只读 spliced 即不重复计数；首跑未分载体、样本从 51 虚增到 88，该口径已弃）。

结果：

- advice 注入 = 51 次，覆盖 4 个技能、21 个会话（prose-standard 16 / archive-agent-notes 16 / doc-standards 12 / pre-push-checks 7）。
- 其中 **47/51（92%）** 在同一会话卷内随后出现同技能载入。未后续载入 4 例全部集中在同一卷（`8156897a`），且其中 1 例该技能在该卷此前已载——与「宿主 supervisor 恢复新起子进程 → 插件每会话态复位」同向（2026-09-12 journal 在案），故注入事件的分母本身带该噪声。
- 独立佐证：journal 对 `f6ea2796` 一卷的前批留痕记「advice 当场触发且照办」，与本口径的 seq 比较逐条相符。
- 代价面：session-close 各卷记的「该载未载」逐条复核——**零件归因到返工**（多卷明写「未产生返工」/「未返工」）；两例记有评审代价（R3 抓出的文档面 Suggestion ×4、三路措辞与口径类 S），但两例都发生在触发面扩面批**之前**、当次**无 advice 发行**（零触发面形态），故不构成 T1 命中。缺口构成是——(a) 结构性触发盲区（`.md` 散文面 / `git push` 命令面 / bash 重定向目标通道，已由触发面扩面批 + 推送修复件闭合）；(b) 任务型泳道技能（`noo-code-review` / `noo-find-simplifications` / `noo-trim-cot-leakage`）由子系统按指令载入、主会话本不该载；(c) 取证段「无对口技能可载」；(d) 守卫面结构不覆盖的形态——脚本体内的写（python heredoc 的 `sub(path, …)` / `sed -i`）与读命令面，即触发面扩面 ADR 已具名的残余边界。

## Decision

1. **不升阻断档，维持单次 advice**。HERO 两问：检测的具体失败 = 「advice 已发行 → 技能未载 → 同类写入继续」——该形态有可复算实例（51 中的 4），但**这 4 例零代价归因**（带评审代价的两例发生在 advice 发行面存在之前，见 Problem 代价面）；真出现后下一步不同 = 拦回该次写入并回模型可见消息。判不立的根据 = 命中面是**语义代理**（路径前缀 / 后缀 / 命令正则），不是客观违规判据——A4 block 先例可迁移的前提是「违规由 lint 客观判定」，本面无对应物；把启发式命中升成硬拦回即过度防御（HERO 核心判据：说不出必报失败就别建）。
2. **服从面证据即本件交付**：92% 服从率说明 advice 档在有效工作；缺口已由触发面扩面批 + 推送修复件收敛到结构面，本批不再动机制。
3. **升格触发具名**（满足任一即重开本项）：
   - **T1（代价触发）**：session-close 对账记录到「advice 已发行、该技能未载、且关联写入在评审/门禁/返工上留下可指名代价」的实例 ≥1（附会话卷与证据行）。
   - **T2（判据触发）**：出现「写 X 却不载 Y 一定错」的客观判据，使命中面不再是语义代理。
   - **T3（噪声反向触发，动作 = 收窄触发面而非升格）**：按 Problem 节同法复算得某技能的 advice 服从率跌破基线——判据 = 该技能累计发行 ≥5 次且后续照办 <50%（基线 = 本件 47/51 ≈ 92%）；复算责任面 = session-close 对账步。
4. **本件不改机制**：`skill-guard.mts` 与 `config.skillGuards` 零改动；档位与「每会话每技能至多一次」的噪音纪律不变。

## Alternatives considered

- **升阻断档（重复违约 → 拦回写入）**：落败——见 Decision 1；观测面 92% 服从 + 零代价，收益与成本反向。
- **折中：第二次同类命中再发一行 advice（非阻断）**：落败——未后续载入仅 8% 且零代价，而「重复提醒稀释真守卫信号」是立项 ADR 具名的风险面；且改 `adapters/**` 属 FULL 变更，成本高于观测收益。
- **按「重复违约」字面升格（同会话同技能 ≥2 次命中即拦）**：落败——「重复命中」在观测里主要来自插件态复位后的重发行（前述噪声）与长会话的正常多次写入，不构成违约证据；按其升格会拦合法写入。
- **撤掉守卫（回全自觉档）**：落败——92% 被照办、发行面精确（51 次 / 183 份 v3 卷），触发面扩面批后结构性盲区已闭。
- **把「advice 发行 ↔ 后续载入」纳入 session-close 对账步**：落败——对账步已列本会话技能实调；发行面可按本件同法从宿主卷复算（本评估即先例），加一行流程卡 = 改行为契约面换零新增证据面。
- **只立行动区待办一条**：落败——升格触发需具名证据面与时刻，待办条没有触发时刻（触发面扩面批同款裁决）。

## Consequences

- 批次表行 9 标 done（指针 = 本件）；「未交付」计数 38 → 37。
- 机制零变化：`gates.json`、命令面、`adapters/**` 均不动；本件 LIGHT 档（纯文档收口）。
- 升格决策的证据面即 T1–T3；复算口径 = Problem 节的宿主卷比较法（注入事件 vs 技能载入事件按 `seq`），不新增脚本或记录件。
- 残余现象（非缺陷，本件不动）：插件每会话提醒预算活在进程态里，宿主 supervisor 恢复后复位，同一技能在同一会话卷内可重发行（观测 3 卷，其中 1 例该技能此前已载）——advice 非阻断且每卷有界，代价近零；若 T3 复算显示它拉低服从率读数再评估。
- 残余边界维持具名：脚本体内的写（python heredoc / `sed -i`）与读命令面不产生触发事件（触发面扩面 ADR Consequences）——本件不为它们升格。
