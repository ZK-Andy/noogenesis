# Agent Note: 阶段卡结构规范——步序 / 角色位 / 关口

Status: implemented
Review: FULL/2026-09-11/pending（三重审核进行中，收口时回填真实结论）

Related: 法规家 [doc-standards](../../../../docs/method/doc-standards.md) §2 铁律 7（写作规则）+ 根 [AGENTS.md](../../../../AGENTS.md)「评审检查项」第 6 条（评审兜底）；被改的卡 [feature-flow](../../../workflows/feature-flow.md) §5 与 [session-close](../../../workflows/session-close.md) §3/§10；前因 [吸收阶段 ADR](2026-09-11-absorption-stage.md)（本件修其落地的形态缺陷，决定不变）；触发本件的会话事实 [journal 2026-09 卷](../../../../journal/2026-09.md)。

## Problem

**触发**：吸收阶段在 2026-09-11 两批里连续以「先提交推送、后汇报」的形态走完（本会话两次均由用户点名），根因定位到**卡的形式层**：

- **§5 没有步序**：`feature-flow` §1–§8 是编号节，§4 内部还有 `4.1 定档 / 4.2 范围 / 4.3 简报先行 / 4.4 并行与报告 / 4.5 等待纪律`——步序显式；§5 只有「四出口清单 + 产出 = 吸收账（…随批汇报）」+ 一句不新增评审代理，**没有第一条、第二条，没有先后**。让「先获用户确认、再执行出口、才进提交」在卡里无处安放。
- **规则里「人」零出现**：`grep 用户|确认|点头|批准` 扫 §5 + `session-close` + 吸收 ADR，命中的只有收尾汇报与推送提醒；规则唯一提到人的地方是「随批汇报」——把人写成**读者**，不是阶段的**参与者**，读者没有关口。
- **无规范管卡的结构**：`doc-standards` 的 tier 表只管内容放哪层，`standard-authoring` 只管强制力度分档——**没有一条规定流程卡/阶段卡必须写成有次序、有角色、有关口的步骤**。§5 是「合规地写漏了」。
- **评审清单不覆盖机制结构面**：根 AGENTS 的 5 条兜底检查项按产物类型组织（文档纪律 / ADR 口径 / 规范与门禁口径一致 / 编码注释 / 防过度设计），**没有一条问阶段的内部结构**。后果有实证：上一轮重建吸收阶段的那份 ADR **被三路 FULL 完整审过**（含专审 ADR 的 R3），本缺陷未被任何一路提出。

**因果链（为什么同一类偏差复发）**：上一轮把「吸收被降格为 §4.6 子步」判为偏差，诊的是**位置层**，修法是把阶段提到与 §4 同级。**位置修了，形态没修**——§5 与 §4 平级，内部却没有 §4 的步序。阶段被描述成**名词**（位置 + 出口清单 + 产出物）而非**动词序列**（次序 + 角色 + 关口）；名词化的阶段自动被按最低成本解释（账 = 产出物 → 「随批汇报」＝收尾汇报一段 → 阶段走完）。漏了也没人知道：§4 的次序有机器面兜（简报闸发射前过闸、tier 闸 push 前拒推缺证据），**§5 零机器面**，`session-close` §3 的吸收对账是自证且时点在推送之后（§8）。

## Decision

1. **写作规则（怎么写）**：`doc-standards` §2 增铁律 7——流程卡/阶段卡写成步序，不写成名词清单；每阶段必须写明**步序**（谁先谁后）、**角色位**（哪步是人、哪步是 agent）、**关口**（哪一步停下等确认/等闸过，未过不得继续）；「产出 = 某物」不构成完成判据。
2. **§5 重写为四步序（含人工关口）**：① 出账（主会话）→ ② **呈报与确认（主会话 → 用户）〔关口〕：未获确认前不得执行出口、不得进 §6 提交** → ③ 逐出口执行 → ④ 回执（每条落点随批汇报，作为 §8 前置门判据）。四出口清单保留为出口判据。
3. **对账与汇报面同步**：`session-close` §3 的吸收对账改为按**回执**核（账已呈用户确认 + 四出口各已执行，不再只核「账已出」）；§10 收尾汇报字段增「吸收账回执」。
4. **评审兜底（怎么查）**：根 AGENTS「评审检查项」增第 6 条——新增/改写阶段卡与机制件时核对步序 / 角色位 / 关口是否齐（规则家 = 铁律 7），机制件是否有匹配的机器面或对账点。**「怎么写」与「怎么查」两处同时补**：只补其一，下一次仍会以别的面孔漏。

## Alternatives considered

- **只改 §5 措辞（加一句「先与用户确认」）**：落败——写作规范缺位时，同一缺陷会在别的阶段/机制件上换面孔复发（本件 Problem 的因果链即此），且评审清单仍无判据可查。
- **只在评审清单加条目**：落败——没有写作规则，评审提出的「结构不齐」没有可引用的判据，裁断回到各人印象。
- **把阶段结构规则放 `review.md`**：落败——`review.md` 是评审面（定档/简报/裁决）的家；「卡该怎么写」是写作规则，归 `doc-standards` 写作铁律。
- **给 §5 加机器闸（闸读吸收账）**：落败——账是判断产物、形状不可枚举，机读判据不稳（同「变更史词面闸」判不立的前案）；关口的时点由卡与 §3 对账兜，不新造闸。
- **把「人工关口」写成 §4 的子步（回到评审节内）**：落败——正是上一轮被判不成立的位置缺陷；§5 与 §4 同级是已拍板形态。

## Consequences

- 本会话两次「先推后报」的两处根因各自有着落：无步序 → 铁律 7 + §5 四步序；无规范/清单覆盖 → 铁律 7 + 检查项第 6 条。
- 自本条起，阶段卡类变更的 FULL 评审按检查项第 6 条显式核对结构面；`doc-standards` 铁律 7 同时是裁断依据。
- 吸收账本身仍无机器闸（判据不稳，如实记）：把关口落在卡与对账面，不宣称机器已盖。
- 「产出 = 某物」不再是任何阶段的完成判据；§8 收尾前置门按 §5 回执核。
