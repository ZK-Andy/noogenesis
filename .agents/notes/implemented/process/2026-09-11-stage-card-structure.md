# Agent Note: 阶段卡结构规范——步序 / 角色位 / 关口

Status: implemented
Review: FULL/2026-09-11/R1=ok R2=ok R3=ok

Related: 法规家 [doc-standards](../../../../docs/method/doc-standards.md) §2 铁律 7（写作规则）+ 根 [AGENTS.md](../../../../AGENTS.md)「评审检查项」第 6 条（评审兜底）；被改的卡 [feature-flow](../../../workflows/feature-flow.md) §4.6 与 [session-close](../../../workflows/session-close.md) §3；前因 [吸收阶段 ADR](../../archived/process/2026-09-11-absorption-stage.md)（已归档；四步序与四出口随 [撤除 ADR](2026-09-12-absorption-async-round.md) 撤除，本件的铁律 7 与检查项第 6 条保留）；门槛与前案 [发现机械化 ADR](2026-09-11-review-finding-mechanization.md)（立闸门槛 + 「变更史词面闸」判不立案）；会话事实 [journal 2026-09 卷](../../../../journal/2026-09.md)（本会话两次「先推后报」与吸收阶段重建批的三路 findings 明细在案）。

## Problem

**触发**：吸收阶段在 2026-09-11 两批里连续以「先提交推送、后汇报」的形态走完（journal 2026-09 卷同名两节在案，两次均由用户点名），根因定位到**卡的形式层**：

- **§5 没有步序**：`feature-flow` §1–§8 是编号节，§4 内部还有 `4.1 定档 / 4.2 范围 / 4.3 简报先行 / 4.4 并行与报告 / 4.5 等待纪律`——步序显式；§5 只有「四出口清单 + 产出 = 吸收账（…随批汇报）」+ 一句不新增评审代理，**没有第一条、第二条，没有先后**。让「先获用户确认、再执行出口、才进提交」在卡里无处安放。
- **规则里「人」只作为读者出现**：`grep 用户|确认|点头|批准` 扫 §5 + `session-close` + 吸收 ADR，命中项全是收尾汇报、推送提醒、「工作树确认」这类受告知位置；规则里把人与阶段动作相连的只有「随批汇报」——人被写成**读者**而非**参与者**，读者没有关口（结论 = 吸收阶段无人工关口）。
- **无规范管卡的结构**：`doc-standards` 的 tier 表只管内容放哪层，`standard-authoring` 只管强制力度分档——**没有一条规定流程卡/阶段卡必须写成有次序、有角色、有关口的步骤**。§5 是「合规地写漏了」。
- **评审清单不覆盖机制结构面**：根 AGENTS 的 5 条兜底检查项按产物类型组织（文档纪律 / ADR 口径 / 规范与门禁口径一致 / 编码注释 / 防过度设计），**没有一条问阶段的内部结构**。后果有实证：[吸收阶段 ADR](../../archived/process/2026-09-11-absorption-stage.md) **被三路 FULL 完整审过**（含专审 ADR 的 R3），本缺陷未被任何一路提出（三条 findings 明细 = 同名 journal 节）。

**因果链【推断 · 未证】**（依据 = 上四条结构证据 + 本会话两次执行形态；未做对照实验）：上一轮把「吸收被降格为 §4.6 子步」判为偏差，诊的是**位置层**，修法是把阶段提到与 §4 同级。**位置修了，形态没修**——§5 与 §4 平级，内部却没有 §4 的步序。阶段被描述成**名词**（位置 + 出口清单 + 产出物）而非**动词序列**（次序 + 角色 + 关口）；名词化的阶段被按最低成本解释（账 = 产出物 → 「随批汇报」＝收尾汇报一段 → 阶段走完）。漏了也没人知道：§4 的次序有机器面兜（简报闸发射前过闸、tier 闸 push 前拒推缺证据），**§5 零机器面**，`session-close` §3 的吸收对账是自证且时点在推送之后（§8）。

## Decision

1. **写作规则（怎么写）**：`doc-standards` §2 增铁律 7——流程卡/阶段卡写成步序，不写成名词清单；每阶段必须写明**步序**（谁先谁后）、**角色位**（哪步是人、哪步是 agent）、**关口**（哪一步停下等确认/等闸过，未过不得继续）；「产出 = 某物」不构成完成判据。**义务面 = 新增与改写的阶段卡**；存量卡在下一次被改到时一并补齐（不设专项 retrofit 批）。
2. **§5 重写为四步序（含人工关口）**（**本条载体已撤除**：条款随 [撤除 ADR](2026-09-12-absorption-async-round.md) 失效，规范文本家当时 = `feature-flow` §5）：出账 → **呈报与确认〔关口〕** → 逐出口执行 → 回执。其中：确认以**整账**为单位，未确认不得执行出口、不得进 §6 提交；机械校验项的**噪声实测结论在出账时给出**；执行期出现与账不符的改判（新事实、判据不成立等）**回关口重新确认——实际执行的去向必须等于确认内容**。四出口清单保留为出口判据（家 = §5）。
3. **对账与汇报面同步**（家 = `session-close` §3/§10）：§3 吸收对账按**回执**核（账已呈用户确认 + 四出口各已执行 + 逐条落点）；§10 收尾汇报字段含「吸收账回执」。（**本条已随 [撤除 ADR](2026-09-12-absorption-async-round.md) 失效**：§3 改按 `feature-flow` §4.6 对 findings 去向，§10 该字段删除。）
4. **评审兜底（怎么查）**（家 = 根 AGENTS「评审检查项」第 6 条）：新增/改写阶段卡与机制件时，核对步序 / 角色位 / 关口是否齐（规则家 = 铁律 7），机制件是否有匹配的机器面或对账点（门槛家 = [发现机械化 ADR](2026-09-11-review-finding-mechanization.md) Decision 1）。**「怎么写」与「怎么查」两处同时补**：只补其一，下一次仍会以别的面孔漏。
5. **取代分类与指针**：本件**不改** [吸收阶段 ADR](../../archived/process/2026-09-11-absorption-stage.md) 的决定（与 §4 同级 / 四出口 / 立闸门槛——该组决定随 [撤除 ADR](2026-09-12-absorption-async-round.md) 撤除，本件保留铁律 7 与检查项第 6 条），同步其 Decision 5 的产出与时点表述并在其 Related 补入站指针。
6. **占位 Review 形态登记**：评审在飞期间 ADR 头部可写**占位** Review 行（形态单源 = `review.md` §1；占位不计证据，收口必须回填真值）——该形态此前无家（历史两件 ADR 各自写占位，判据面零登记）。

## Alternatives considered

- **只改 §5 措辞（加一句「先与用户确认」）**：落败——写作规范缺位时，同一缺陷会在别的阶段/机制件上换面孔复发（本件 Problem 的因果链即此），且评审清单仍无判据可查。
- **只在评审清单加条目**：落败——没有写作规则，评审提出的「结构不齐」没有可引用的判据，裁断回到各人印象。
- **把阶段结构规则放 `review.md`**：落败——`review.md` 是评审面（定档/简报/裁决）的家；「卡该怎么写」是写作规则，归 `doc-standards` 写作铁律。
- **给 §5 加机器闸（闸读吸收账）**：落败——账是判断产物、形状不可枚举，机读判据不稳（同 [发现机械化 ADR](2026-09-11-review-finding-mechanization.md) 记录的「变更史词面闸」判不立前案）；关口的时点由卡与 §3 对账兜，不新造闸。
- **把「人工关口」写成 §4 的子步（回到评审节内）**：落败——正是上一轮被判不成立的位置缺陷；§5 与 §4 同级是已拍板形态。
- **给存量卡做专项 retrofit 批（把 session-open / release-flow / github-research 一次补齐）**：落败——存量卡答不出「会检测出什么具体失败、真出现了下一步做什么不同」（防过度设计核心两问），全称义务落到存量面即过度设计；按「下一次被改到时一并补齐」处理。

## Consequences

- 本会话两次「先推后报」的两处根因各自有着落：无步序 → 铁律 7 + §5 四步序；无规范/清单覆盖 → 铁律 7 + 检查项第 6 条。
- 自本条起，阶段卡类变更的 FULL 评审按检查项第 6 条显式核对结构面；`doc-standards` 铁律 7 同时是裁断依据。
- findings 去向与演化轮候选面仍无机器闸（判据不稳，如实记）：把关落在卡（`feature-flow` §4.6）与 `session-close` §3 对账面，不宣称机器已盖。
- 「产出 = 某物」不再是任何阶段的完成判据；收尾前置门（`feature-flow` §7）按评审通过 + 修复收口（CI 绿）核。
- 存量流程卡（`session-open` / `release-flow` / `github-research` / `feature-flow` §1–§3/§5/§6）保持现状，无 retrofit 义务；被改到时按铁律 7 补角色位与关口。
