# Agent Note: 框架重建立项——推倒重建、先框架后协作层、范围三件套

Status: proposed

## Problem

胶囊 01 优化轮（[docs/research/capsule-01-optimization-round.md](../../../../docs/research/capsule-01-optimization-round.md)）调研收口后，方案设计阶段存在范围级未决：优化路线是「现有框架增量演化」还是「参考 DSH 完全推倒重建」（§2.2-7 用户信号在案，两路线并存未取舍）。增量路线的隐含代价已被实测证据否定：

- **零损失搬迁实验（§3.10，实测审计）**：拷出七层体系审计出 1324 处断链（notes 1129 / docs 112 / AGENTS 层 43 / skills 40）——可搬迁的是方法论本身，搬迁形态 = 蒸馏 + 适配 + 门禁重建。
- **混合态未经语言设计决策（§2.2-6 血统考古）**：Python 门禁 + bash 脚本 + JS 双模块（CommonJS engine / ESM adapters）是两次独立事件的叠加，非设计产物。
- **挂载面利用率为零（§3.4）**：适配层仅接 system-prompt 节 + noo_* 三工具 + agent/created；DSH 的 pre-step waterfall / tool ordered pre / hooks 桥全部未接——问题池七条（技能守卫、规范事前接入、评审实质执行）根因同此。

同时存在一个时序未决：框架蓝图与协作层工程谁先建。以及一个范围误判风险：把「重建」等同于「工程迁移到 TS」——语言债（Python 13 件 + bash 3 件 + 调用同步面）只是协作层工程件，问题池的核心缺口（挂载面、守卫、规范接入）均非语言问题，只迁语言则问题池零消解。

## Proposal

**用户拍板（2026-09-06）：推倒重建；先框架、后协作层；框架重建 = 三件套，语言迁移只是其中一件。**

1. **蒸馏蓝图**：七层框架（常驻 / 决策记忆 / 技能 / 门禁 / 流程 / 教训 / 运行时守卫）照 DSH 已验证形态落本仓版本；设计冻结在「足以钉死协作层需求」的深度——七层蓝图 + 挂载面清单 + 协议定案即停，协作层重建本身是蓝图的迭代验证器。
2. **挂载面与守卫设计**：框架重建真正的增量设计面。口径 = **能力层全接，策略层逐件增挂、每件带判据**——适配层把 DSH 全部机器触发点接上（agent/pre-step waterfall、tool/call ordered pre、packages/hooks 桥、停止前）；每个挂载物必须回答 HERO 核心判据（「这次运行会检测出什么具体的失败？真出现了下一步会做什么不同的事？」），答不上不挂。首批挂载物只挂调研已实锤三件：技能使用守卫（②该不该用/③用了没有）、规范事前接入落点、评审实质执行记录件；提醒档（repeat-tool-reminder 类）逐件评估再挂。
3. **工程 TS 化**：协作层重建首件实现，作为蓝图第一个验证宿主。既定约束（§2.2-6）随迁：全栈 TS、tsx 只属开发态、**钩子永远跑预构建 dist（零转译）**、门禁 DAG 并行、bash 三件退役、postinstall 自动装钩子、发布走 tsc dist。

**时序**：先框架（设计轮出蓝图 + 挂载面设计 → 拍板落 ADR）→ 后协作层（实现轮）。规范事前接入展开、记忆库线、技能清单补全三件排在重建后进行；技能清单「等等」项为用户输入件，不占重建道，随时可给。

**实施载体（用户拍板 2026-09-06）：本仓原地重建**——机器层（engine / scripts / hooks / CI / npm 管线 / adapters）分批重建，资产壳（docs / .agents / journal / genes / gates.json / 事件轨）零搬迁；切换用发版断点标记（rebuild cut），不冻结仓。依据：重建触及面恰是仓内最小部分，而新仓方案要动全部资产接线（npm repository 重指、基因库仓迁移、journal/ADR 跨仓分裂）——第三次搬家无设计收益，只有搬迁成本。并存期权威归属须显式标注，切换走单批（新机器自测对账后一次删除旧机器），不长期双轨。

**余项（框架设计轮内出方案）**：蓝图深度冻结点与既有资产（6 基因、gates.json、事件轨、评审三审历史）的对接口径；挂载面全清单与首批挂载物设计。

## Alternatives considered

- **增量演化**（在现有框架上做 §2.2-1~6）：落败——§3.10 实测 1324 断链证明缝补路径不可行；混合态从未经过语言设计决策；旧适配层上加挂载点是脏改（守卫需求反过来拆已建接线）。
- **先协作层后框架**：落败——协作层是框架的执行基座，框架是协作层的需求源；反序则蓝图一推进就得拆已建接线返工，且 self-hosting 验证顺序要求蓝图先行、协作层重建每步有判据可对。
- **重建 = 只做 TS 迁移**：落败——语言债清完但问题池核心缺口（挂载面/守卫/规范接入）原封不动，是 HERO 过度设计教训的镜像（漏建）；TS 迁移降级为三件套之一。
- **挂载物也「尽量多」**：落败——挂载点全接后最省事的滑坡是堆 advice-never-block 提醒噪声，重复提醒稀释真守卫信号（HERO：具体指令压过泛化偏好）；策略层逐件过判据是能力层全接的对价。
- **再开新仓重建**：落败——纯洁性买不到东西（本仓机器层体量小、活了两日，「旧仓包袱」近零），代价全是搬迁 churn：npm 包 repository 重指、基因库仓迁移（P2 刚拍板「本仓即库」即需改口）、journal/ADR 跨仓分裂（过程资产断链，cookbook 在案的反模式）、用户远端仓重指。

## Acceptance criteria

- 框架重建设计轮产出：七层蓝图（冻结深度按 Proposal 1）+ 挂载面全清单（能力层）+ 首批挂载物设计（每件带 HERO 判据答案）→ 拍板落 ADR，本 ADR 转 implemented。——**已达成（2026-09-06 用户拍板）**：蓝图 [framework-rebuild-blueprint](../../../../docs/research/framework-rebuild-blueprint.md) 定稿（七层三段式 + A1–A8 挂载面全清单 + M1–M3 首批挂载物 + C1–C14 协作层验收需求），实施载体同日拍板（本仓原地重建）；本 ADR 随收口评审批转 implemented。
- 协作层重建实现轮的验收以蓝图判据对账：挂载点覆盖面、协议语言无关性（6 基因与事件轨零改动）、钩子跑预构建 dist。
- 问题池七条在重建链路中逐条有归口（首批挂载物三件 + 重建后三件 + 事实面留档一条），不因重建轮收口而悬空。

## Risks

- 蓝图过度设计（HERO「重流程压过泛化克制」）：设计轮必须冻结深度，留白优于写满；冻结点 = 钉死协作层需求。
- 重建并存期漂移：蓝图落地到单批切换的窗口内，新旧机器权威归属须显式标注（蓝图判据 vs 现行门禁），切换批一次收口、不长期双轨。
- 载体已拍板（本仓原地重建），无搬迁类悬空风险；切换批失败的回退路径 = git 断点 revert（资产壳未动，回退只涉机器层）。
