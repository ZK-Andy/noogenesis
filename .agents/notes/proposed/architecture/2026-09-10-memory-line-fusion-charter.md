# Agent Note: 记忆库线融合立宪——按机制收、按两半裁

Status: proposed

## Problem

记忆库线方向已拍板（2026-09-10）：与冻结的 `dsh-continual-evolve@0.6.0`（下称旧引擎）走融合轮；本地记忆库立项与本仓 memory-graph 最小版均否决。悬空的是**融合边界的形态**——设计稿 [§13.5](../../../../docs/research/dsh-swarm-evolution-framework-design.md) 留的是「协议层放同一插件还是独立插件；及其与旧引擎的融合顺序」，而平级形态（谁大谁小、谁先谁后）回答不了更硬的一问：**融合会不会把旧引擎的历史缺陷带进来**。

缺陷有存档，且不在代码层：

- work 区 `HANDOFF.md` 第 18 条（2026-09-04，用户实机反馈）：**token 消耗过高**（门禁每 N 回合 LLM 调用 + fate + wrapup，成本常开）；**自动沉淀的记忆没有产生过可追溯收益**——「刚开始的沉淀完全是错的」。诊断 = 沉淀对象选错 + 成本结构倒挂（确定性常开成本 × 概率性稀有收益）；真正产生过收益的全是手工策展紧凑资产（流程卡 / verify 脚本 / 踩坑）。
- 本仓 cookbook 同源两条：自动蒸馏零可追溯收益、token 成本倒挂；自由沉淀导致技能爆炸（[cookbook](../../../../docs/cookbook.md)）。
- work 区 `OBSERVATION.md` 形态结论：交接/流程类知识被沉淀成 harness skill 条目，而「memory 指引 ≠ skill 流程，形态不同而门禁不区分」。

旧引擎的能力实为两半：**A 半 = 自动沉淀面**（autoReview 常开门禁 / fate 命运判定 / wrapup 自动晋升 / 会话记忆作为沉淀对象），**B 半 = 治理与评估面**（原子写 / 快照 / 确定性回滚 / 审计事件 / 写入守卫 / 两段式评估协议 / 注入预算）。上列缺陷全部落在 A 半；B 半在[搬迁计划 §5.7](../../../../journal/capsule-01-migration-plan.md)已被标为「不搬，只对标」的设计参照。据此：**按仓库整体融合会带进缺陷，按机制逐件收不会。**

## Proposal

**D1（2026-09-10 拍板）融合方式 = 按机制收，不按仓库收。** 融合对象是机制清单，不是旧仓代码整体。

**D2 不收清单（A 半全家）**：autoReview 常开门禁、fate 自动命运判定、wrapup 自动晋升、会话记忆作为沉淀对象、自由沉淀成技能。不收即其缺陷自消——token 常开成本、零可追溯收益、形态混乱三条随之消失（与 P1 D2 禁区「人就是信号源」同向）。

**D3 收清单（B 半机制，逐件带吸收补丁）**：吸收要求 = 该机制进仓时同批修掉的缺陷，来源为本轮对旧引擎 `0.6.0` 源码的只读对抗审计（`src/` 42 件，`path:line` 证据可复现）。

| 机制 | 吸收要求 |
|---|---|
| 原子写 + 快照 + 确定性回滚 | 快照只写不读、无修剪、无测试，回滚实际依赖 `refinements.jsonl`；且先存状态、后追加结果记录——一次 ENOSPC 即永久不可回滚。要求 = 快照要么删、要么读 + 断言 + 修剪，且结果记录与状态保存原子落地 |
| 写入守卫（schema / scope 一致性 / 近重复 / 推广策略） | 存在结构性旁路：`/evolve import` 无校验、无筛查、无快照、无审计、无审批地整文件替换 store；模型可调用的 rollback 不过审批。要求 = 单一写入口，守卫结构性不可绕过 |
| 凭据筛查 | 只覆盖 global 面、只认带引号赋值，漏 env 式赋值 / JWT / 连接串内嵌凭据；落盘 0644。要求 = 只当 best-effort 绊线，不作安全属性；入 git 面不得承载凭据 |
| 乐观并发守卫 | 全部 global writer 都传不到基线；多进程 / 多实例同 home 丢更新。要求 = 单写入口 + 显式基线 |
| 审计事件轨 | 归本仓 `events/` 演化轨（D5），旧仓 `reviews.jsonl` 不并入 |
| 两段式评估协议 | 收「执行者不见 rubric / 独立评分者 / 失败格不计零分 / 冻结基线」；同时钉死两条强度上限：评分为**模型判断**（非宿主确定性），reviewer 与被测同 provider / model；rubric key 与密文同树 = 混淆而非隔离 |
| 注入预算与出口 | 收机制（order 分配、零 token 空态、目录上限、使用计数），不收其排序与预算参数（归胶囊策略层） |

**D4 换触发与对象**：沉淀机制保留；**触发权**从「每 N 回合自动」改为**人 / 显式目标触发**（对齐 P1 D2「人就是信号源」，[骨架 ADR](../../implemented/architecture/2026-09-05-p1-engine-skeleton.md)）；**沉淀对象**从「会话记忆」换成**可机械验证资产**——流程卡 / 门禁脚本 / 踩坑，载体分别为 gene / method 文档 / cookbook。

**D5 memory-graph 的家 = 本仓 `events/` 演化轨**（2026-09-10 拍板）：gene 因果与 gene 同轨（git 可读、机器可复算、离线 Select 不依赖宿主 home 状态）；旧仓证据只作 evidence 指针，不搬家。

**D6 旧仓形态 = 冻结参照**：不并代码、不并 store；旧引擎 `v0.6.0` 维持冻结。

**D7 接口契约（2026-09-10 拍板）**：融合的接口面收敛为**四类**，其中两类现在生效、两类判暂不立。四类中三类是**向内接口**（新机制插进本仓既有单源面），仅一类向外。

1. **审计事件轨（向内，现定）**：kind 准入判据 = **写得出复算规则才进轨**（继承 [schema ADR S2](../../implemented/architecture/2026-09-05-gene-event-schema.md)「演化事件 ≠ 运行日志」）；`gene.used` / `gene.outcome` 这类不可复算事件不进轨，只走人工确认或适配层证据行。memory-graph 的边是**派生数据**而非事实：Select 时现算（可选 gitignored 缓存），**不进 git**（避免与事件轨双记账）。
2. **验证面（向内，现定）**：行为评估**落在适配层**——可复算部分物化为 `engine/gates.json` 白名单内的验证命令（引擎照旧只认 exit code），LLM 判断部分只作 solidify 事件的 `evidence` 指针，引擎不消费不判定。两条合同不因融合松动：引擎依赖面（零网络 / 零第三方依赖）与「入档条件 = 门禁全绿」。
3. **宿主挂载面（向外，暂不立）**：两边当前不同 profile（旧引擎在 `web` profile、本仓在 `dotnet-desktop`），冲突面（工具名 / 命令 / 注入 order / 审批 question id / 审计文件 / 技能面 / 服务键）属未来时；**触发 = 两者同装即办**。现只钉两条零成本规则：命名前缀沿用 `noo-*`（胶囊）/ `dsh-*`（生态插件体）；两边各自声明审计文件的单一真相源。
4. **向外只读证据面（暂不立）**：旧引擎无 subpath 导出、kind 为封闭联合、store 路径硬编码，**不可能 import**；其文件（`reviews.jsonl` 的 `evolve_complete` 等）只能作 `evidence` 指针——二手家，与 D5 冲突，不作事实源。

**待拍板（显式挂起，拍板前不启动实现）**：

1. 机制的**代码归属**：D7 后只余一个自洽落点（两类现定接口均为向内接口，向外两条判暂不立）——**倾向本仓**，待用户确认。
2. **痕迹提炼面归属**（用户 2026-09-10 拍「本轮定不了」——本 ADR 只钉它须落在 D4 的触发与对象口径内）。
3. 实现顺序与第一期交付物，另含 D7-2 的**直接后果**：行为评估需自建（旧引擎 rubric / 子代理机制只作参照），其形态与第二期范围须一并裁。

## Alternatives considered

- **甲 吸收式合并**（旧仓整体并入本仓成唯一插件）：与 D2 冲突——整体并入即把 A 半整套带进来；库体量与评审负担另计。
- **乙 双插件分工**（两插件平级、各守一层）：用户否决——框架与胶囊是包含关系而非平级；两套注入节（旧引擎 order 118/119、本仓 120/121）、两套审计轨、两个技能源、单例工具名与审批 id 的冲突面换不来收益。
- **丙 上游先行**（在旧仓做融合版再回收）：本仓门禁与评审管不到旧仓代码，self-hosting 分裂（框架在本仓、实现在旧仓）。
- **丁 旧仓整体成为胶囊**：被否——autoReview / fate / wrapup 是该胶囊自身的策略，胶囊化会把 A 半整套打包；「按机制收」天然允许逐件裁剪。
- **只做协议对接、不收机制**：落败——B 半是成熟实现（原子写 / 回滚 / 两段式评估），自建成本高；其缺陷经本轮审计已可逐条点名，无需靠回避规避。

## Consequences

- 本轮 11 项审计发现按半分流：A 半缺陷随不收清单**自消**；B 半缺陷转为**吸收补丁**（D3 表）；第三类**形态成本**（无锁、全量重解析、注入面多次 tokenize 全 store、宿主事件名未版本化导致静默降级）在实现轮逐条给机器可判形式，或显式标注为评审面。
- 旧引擎历史缺陷以**禁止清单**形态落本仓，而非「小心避开」；与本仓 cookbook 两条同源，评审可回指。
- 双审计轨问题不再成立：只留本仓 `events/` 轨。
- **接口面收敛（D7）**：一个写入口（事件轨）+ 一个校验面（白名单 + 行为评估物化）+ 一套挂载预留规则 + 一条只读证据指针；向外两条判暂不立，故融合不需要任何跨插件运行时接口。
- **D7-2 的直接后果**：行为评估需在本仓自建（LLM 判断部分只作 evidence 指针），第二期范围由此出现——实现顺序拍板时须一并裁；旧引擎的 rubric / 子代理机制只作参照实现。
- D3 的补丁要求即实现轮的验收面；若只落 ADR 而无可执行检查，会退化为自觉档。
- 数字强度：本轮测算为**本机单次实测【探索性】**——56 份 global 快照 1.9 MB 对状态文件 61 KB；`refinements.jsonl` 约 4.2 KB/条。
